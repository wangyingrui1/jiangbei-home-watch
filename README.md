# 江北成交观察

面向总价 150 万元以内购房预算的南京江北二手房成交观察站。网站提供成交记录筛选、小区详情、公开来源追溯，以及经核查的真实小区照片和户型图。覆盖按通常所称江北理解，包含浦口、桥林等区域；**地图范围不等于数据已完整覆盖**，实际收录范围取决于可核查的公开来源。

## 数据口径

- 交易数据来自公开页面明确标为“成交”的记录，每条保留原始来源链接、成交日期、观察时间和取证文字。平台公示成交不等于已经政府网签核验，本项目不声称掌握全量真实网签数据库。
- 不把挂牌价、估价、带星号隐藏价格、博主口述价格，或没有明确成交日期的帖子当作已核实成交价。小红书等线索应人工交叉核查后再接入；当前自动适配器处理我爱我家南京公开成交列表，以及房天下明确标注来源的公开成交详情；房天下“市场信息”先进入候选，未经人工核查不作为正式成交发布。
- 总价硬性不超过 150 万元。我爱我家部分总价以整数万显示，和平台单价存在取整差，故保留 `totalPricePrecision: platform_display_rounded` 及平台披露单价；其显示为 **150 万元** 的记录也排除，避免实际金额略超预算。展示值不是精确至元的付款金额。
- 页面中的“最近检查”是系统请求公开来源的时间，“最新成交”是当前样本里最新的成交日期，两者分别显示。每日检查不代表每日有新成交，也不代表平台当日公开全部成交。
- 小区定位、优劣势是注明依据和局限的编辑判断；同一楼盘不同期、楼栋、面积可能差异很大。保留平台原小区分期名 `platformCommunityName`，避免同社区的记录被误当成同一分期。
- 图片只使用已实际核查的公开来源图片并附出处。自动采集不根据缩略图文件名推断户型图；缺图就明确缺失，不生成、不拿其他户型替代。图片的拍摄时间、样板状态和实际在售/成交房屋可能不同，请以原图说明为准。

## 本地运行

需要 Node.js 22 或以上，无第三方 npm 依赖，无需安装依赖。

```bash
npm test
npm run validate
npm run build
npm run serve
```

打开终端输出的本地预览地址。`npm run serve -- --dist` 可预览 `dist/` 构建产物。网站采用相对路径，可部署在 GitHub Pages 的仓库子路径下。

## 每日更新与 GitHub Pages

目标仓库：`wangyingrui1/jiangbei-home-watch`，网站地址：`https://wangyingrui1.github.io/jiangbei-home-watch/`。该地址只有在仓库创建、Pages 配置和部署成功后才可用，请以 Actions 的部署结果为准。

1. 将仓库推送到 GitHub 的 `main` 分支。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 在 **Actions** 中启用并运行 **Daily data and GitHub Pages**。也可用 **Run workflow** 手动检查数据并部署。
4. 工作流计划每天北京时间 **09:17**（UTC 01:17）执行。GitHub 调度可能延迟；最近检查时间以网站的实际状态为准。

同一次工作流先运行测试、检查公开源、校验数据，再仅提交 `data/transactions.json`、`data/status.json`、`data/discovery.json`，最后构建并部署 Pages。自动提交不会依赖另一次 push 工作流来发布，因此检查状态也会在本次部署中更新。更新 job 只有仓库内容写权限，发布 job 才有 Pages 和身份令牌权限；无需个人访问令牌。

登录、验证码、robots.txt 禁止、重定向或限流会使相应来源标为受限，采集器不会绕过限制。访问失败或未找到合格新记录时保留全部历史记录，网站会显示真实检查结果。脚本成功执行只表示完成检查并写入状态，不能据此断言来源数据已更新。关注网站检查状态和 Actions 执行结果。

## 来源维护

`data/sources.json` 每条来源包含适配器类型、公开 URL、是否启用，以及平台精确小区名到本站社区 ID 的审核映射。所有社区 ID 必须已经存在于 `data/communities.json`。遇未知名称不自动猜测、不自动收录。

目前采用有限公开列表样本，不保证翻遍历史分页或覆盖整个江北。增加来源时，先确认 URL 返回对应板块或小区的真实成交列表；无效板块地址可能返回全南京，不能直接接入。检查页面结构、成交日期、价格披露精度、社区映射和图片原始出处，再更新配置。新增适配器应增加离线失败样例测试。人工线索应先完成同样的来源核实流程，可使用人工审核导入命令，详见 scripts/review-format.md；未经审核的帖子不会进入正式平台成交库。

```bash
npm run update
npm run validate
npm test
```

`data/status.json` 保留每个来源的状态、HTTP 状态、候选/合格/新增数量、拒绝原因、响应摘要、最近检查及最新样本日期。网页仍有数据不代表自动更新一定正常；来源受限时历史成交仅供查看。

## 文件

- `index.html`、`style.css`、`app.js`：静态界面与交互。
- `data/transactions.json`：符合预算的已审核成交样本。
- `data/communities.json`：小区资料、分期与图片出处。
- `data/sources.json`：公开来源及审核映射。
- `data/status.json`：最近一次真实来源检查结果。
- `data/discovery.json`：新小区/分期及人工来源候选，独立于正式平台统计。
- `scripts/`：无依赖采集、去重、校验、构建和测试。
- `.github/workflows/site.yml`：每日检查和 Pages 发布。

房价、政策、交通、学区及配套会变化。本站用于公开信息整理和比较，具体房屋情况以线下核验及交易材料为准。
## 新小区发现

板块发现不受首批7个小区限制。每次采集会识别 `communities.json` 全部已审核名称与 aliases，未知名称中只有总价、成交日、户型面积及来源都完整的记录才进入 `discovery.json`。候选可能是旧盘的新分期，不代表已经核查为次新楼盘；建成年代、地理范围与图片仍需逐项核验。

`npm run discover` 只写候选和检查状态，适合在人工整理正式库期间运行；`npm run update` 会同时续采已审核社区的平台记录。首次扩展实际发现了更多公开历史成交，仍未发现可确认预算的2026年9—10月明价记录；星号价和无法取得的价格不会用估算补齐。来源受限时采集器在同域首次拒绝/验证后停止后续请求。

贝壳、链家、小红书保留真实公开入口的访问规则监测；当前通用机器人访问被 robots 禁止，监测不是自动成交抓取。人工可核查的原始公开材料可用 `npm run import:review -- --file 路径 --dry-run` 验证后导入候选。博主/作者自述始终以 `author_reported` 独立标识，不用发帖日替代成交日、不混入正式平台成交统计。完整格式和批准要求见 `scripts/review-format.md`。
